## Context

当前清理逻辑已经存在，但主要按 `retentionDays` 删除旧文件，并在启动和周期性 tick 时执行。这个变更会把清理触发点简化为“上传成功写入之后异步触发”，同时把保留天数清理和容量上限清理合并到同一个清理动作中。

## Goals / Non-Goals

**Goals:**

- 为上传目录增加默认 `5G` 的总容量上限。
- 支持通过配置文件和环境变量覆盖容量上限。
- 在上传成功写入文件后异步触发清理，不让响应等待清理完成。
- 单个清理动作同时处理保留天数和容量上限。
- 移除本次变更对启动时清理和周期性清理的要求，降低实现复杂度。
- 三套服务端实现保持一致行为，不为 Python3/Node.js 引入包管理器依赖。

**Non-Goals:**

- 本次不做任何传输加密或静态存储加密。
- 本次不增加用户级、租户级或文件类型级配额。
- 本次不改变文件列表、下载接口或上传响应结构。
- 本次不要求服务端启动时或定时器周期性执行清理。

## Decisions

### Decision: Add `maxStorageGB` and `MAX_STORAGE_GB`

使用 `maxStorageGB` 作为配置文件字段，并使用 `MAX_STORAGE_GB` 作为环境变量覆盖项。单位固定为 GB，默认值为 `5`，避免在第一版中引入 `5G`、`512M` 等多单位解析差异。

考虑过的替代方案：

- 使用 `maxStorageBytes`：精确但对人工配置不友好。
- 使用自由格式字符串如 `5G`：可读性好，但三套运行时需要实现一致解析，第一版收益不高。

### Decision: Cleanup Runs Only After Successful Writes

所有文件清理都由成功上传写入后异步触发。清理动作内部先删除超过 `retentionDays` 的普通文件，再按容量上限删除最旧普通文件。这样实现只需要一个清理入口和一套调度逻辑。

考虑过的替代方案：

- 保留启动清理和周期性清理：覆盖更积极，但清理触发点更多，三套运行时实现复杂度更高。
- 只做周期性清理：不能满足写入后尽快收敛目录大小的需求。

### Decision: Cleanup Uses One Shared Ordering Rule

容量清理按普通文件的修改时间从旧到新删除，直到总大小低于等于上限或没有可删除普通文件。目录和不可 stat 的异常条目跳过并记录日志。

考虑过的替代方案：

- 按文件大小删除：能快速释放空间，但可能删掉最新上传的大文件，不符合用户预期。
- 清理到 90% 水位：减少频繁清理，但规格更复杂；第一版清理到上限即可。

### Decision: Reject Single Files Larger Than the Storage Quota

如果单个上传文件本身超过容量上限，服务端直接拒绝并删除临时/部分文件。否则即使清空目录也无法满足上限，用户也会看到刚上传的文件立即被清理，体验不合理。

考虑过的替代方案：

- 允许写入后再清理旧文件：对超大单文件无效，会导致目录长期超过上限。
- 允许超限但记录日志：不能防止磁盘无限增长。

## Risks / Trade-offs

- [Risk] 如果服务端长时间没有新上传，旧文件不会仅因时间流逝被主动清理。→ Mitigation: 这是本次简化后的明确取舍；下一次成功上传会触发 retention 和 quota 清理。
- [Risk] 大目录统计总大小可能较慢。→ Mitigation: 清理异步运行，并防止重入；上传响应不等待目录扫描。
- [Risk] 三套运行时清理顺序不一致会导致测试结果不同。→ Mitigation: 统一按修改时间升序删除普通文件，并在测试中构造确定的 mtime。
- [Risk] 上传后异步清理可能删除刚写入之前的旧文件。→ Mitigation: 这是容量上限的预期行为；刚写入文件通常 mtime 最新，不会优先删除。
- [Risk] 并发上传可能短暂超过容量上限。→ Mitigation: 每次成功上传都尝试触发清理，并用非重入清理任务收敛目录大小。

## Migration Plan

1. 在默认 `server.config.json` 中加入 `maxStorageGB: 5`。
2. 为 Go、Python3、Node.js 服务端分别实现配置读取和默认值。
3. 将清理逻辑整理为单个动作：先执行保留天数清理，再执行容量上限清理。
4. 移除本次变更中对启动清理和周期性清理的实现要求。
5. 上传成功后调度异步清理。
6. 添加三套运行时的配置和写入后清理行为验证。

回滚方式：移除 `maxStorageGB`/`MAX_STORAGE_GB` 逻辑和上传后清理触发，保留或恢复原有按天数清理行为。
