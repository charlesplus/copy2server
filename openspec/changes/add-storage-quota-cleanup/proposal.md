## Why

当前上传目录只按保留天数清理，无法限制磁盘总占用；如果持续上传大文件，`uploads` 会无限增长并最终耗尽磁盘。新增存储上限，并把所有清理统一收敛到“成功写入后异步触发”，可以在保持代码简单的同时控制上传目录规模。

## What Changes

- 新增上传目录最大存储上限配置，默认 `5G`。
- 允许通过配置文件和环境变量覆盖上传目录最大存储上限。
- 文件成功写入后，异步触发一次清理动作。
- 清理动作同时处理文件保留天数和上传目录总容量上限。
- 当目录超过容量上限时，优先删除最旧的普通文件，直到低于容量上限。
- 简化清理触发机制：不再要求启动时清理或周期性清理。
- Go、Python3、Node.js 三套服务端运行时都需要保持一致行为。

Non-goals:

- 本次不实现上传传输加密、静态文件加密或 AES-GCM 密钥配置。
- 本次不新增用户级存储配额或按文件类型的配额。
- 本次不新增后台管理 UI 或手动清理按钮。
- 本次不改变下载接口、文件列表响应结构或浏览器上传入口。

## Capabilities

### New Capabilities

- 无。

### Modified Capabilities

- `runtime-configuration`：新增上传目录最大存储上限配置和环境变量覆盖规则。
- `web-file-transfer`：简化自动清理行为，统一在成功上传写入后异步执行清理，并按保留天数和容量上限删除文件。

## Impact

- 代码：三套服务端都需要新增容量上限配置解析、目录大小统计、容量清理和上传成功后的异步触发。
- API：不破坏现有 HTTP 路由和 JSON 响应结构。
- 配置：`server.config.json` 新增最大存储上限配置；现有配置保持向后兼容。
- 运行时：清理只由写入成功后触发，需要避免并发清理重入和删除刚写入的文件。
- 兼容性：Go、Python3、Node.js 服务端应保持相同的清理策略。Python3 和 Node.js 仍不得引入 pip/npm 依赖。
